# DropShopping

인천공항 환승객을 위한 "짐은 맡기고, 환승 시간을 인천에서" 서비스 프로토타입입니다. 도착부터 공항 복귀까지 남는 환승 시간(Time-Safe)에 맞춰 데이유즈 숙소·짐 보관·주변 액티비티를 자동으로 코스로 짜줍니다.

## 폴더 구성

```
DropShopping/
├── app/                  # 프론트엔드 (정적 프로토타입)
│   ├── index.html        # 실제로 실행되는 단일 파일 앱 (React, 빌드 없음)
│   └── assets/           # 앱에서 쓰는 로고 이미지
├── server/                # 인천공항 실시간 API 프록시 서버
│   ├── server.js
│   ├── package.json
│   └── .env.example      # 서비스키 설정 템플릿
└── logo/                  # 브랜드 로고/아이콘 원본 (별도 README 있음)
```

## 프론트엔드 (`app/index.html`)

빌드 도구 없이 브라우저에서 바로 동작하는 단일 HTML 프로토타입입니다.

- React 18 + `lucide-react`를 `esm.sh` / `unpkg` CDN에서 importmap으로 불러오고, Babel Standalone이 브라우저에서 직접 JSX를 컴파일합니다.
- 인터넷 연결이 필요합니다(CDN 로드).
- 실행: `cd server && npm start` 후 브라우저로 **`http://localhost:3001`** 을 엽니다(프록시 서버가 `app/`도 같이 정적으로 서빙합니다). `app/index.html`을 `file://`로 직접 열어도 대부분 기능은 동작하지만, **카카오맵(코스 빌더에서 숙소를 고르면 자동으로 뜨는 지도)은 도메인 등록 때문에 `http://localhost:3001`로 열어야만 뜹니다.**

### 화면 흐름

1. **온보딩** — 언어 선택 → 관심 활동(맛집/마사지/쇼핑/휴식/뷰티/관광/브랜드) 선택 → 환승 항공편 입력 및 **실시간 도착 조회**
2. **홈** — Time-Safe 요약 카드(체류 가능 시간, 복귀 추천 시각), 데이유즈 숙소 추천, 짐 케어 배너, 로컬 투어
3. **예약 / 결제 / 확인** — 데이유즈 숙소 타임블록 결제 및 QR 예약 확인
4. **짐 케어(Luggage-Free)** — 공항 내 보관 / 호텔 배송 / 상권 배송 옵션
5. **코스 빌더** — 데이유즈 숙소를 거점으로 활동 카테고리(맛집/마사지/쇼핑/뷰티/관광/**브랜드**)를 골라 자동으로 환승 일정을 생성(**실제 이동시간** · 체류시간 기반 시간 예산 계산). "브랜드"도 다른 카테고리와 똑같이 방문지 목록·자동 코스 짜기·시간 예산 계산에 들어갑니다(제휴 배지만 별도 표시). 숙소를 고르면 **자동으로** 카카오맵에 공항·숙소 3곳·전체 카테고리 장소 + 주변 실제 카페/음식점이 한 번에 뜨고, 핀을 탭해서 바로 일정에 추가/제거할 수 있습니다.
6. **마이페이지** — 예약 내역, 쿠폰, 알림, 언어 설정 등 메뉴

**숙소(`ROOMS`) 10곳과 활동 장소(`PLACES`) 22곳 전부 실제 존재하는 업체입니다.** 숙소는 영종도/인천공항 인근 비즈니스 호텔(모텔 제외), 활동 장소는 맛집·마사지·쇼핑(면세점)·휴식(캡슐호텔·라운지·찜질방)·뷰티·관광명소·브랜드까지 카카오 로컬 API로 실제 카테고리(음식점/미용/면세점/숙박/관광명소 등)를 교차 확인해서 골랐습니다. 좌표는 카카오 지오코딩·장소검색으로 얻은 실제 위치, 이동시간은 카카오모빌리티/ODsay/도보 추정으로 계산한 실측값입니다. 다만 각 업체의 정확한 요금·영업시간·리뷰수는 공개 예약 API가 없어 여전히 추정치입니다.

### 다국어

온보딩 1단계에서 언어(영/중/일/베/한)를 고르면 온보딩부터 마이페이지까지 전 화면 텍스트와 더미 데이터(숙소명·장소명·파트너명)가 즉시 그 언어로 바뀝니다. 실시간 항공편 데이터도 인천공항공사 API의 `lang` 파라미터(K/E/C/J)를 선택된 언어에 맞춰 같이 넘겨서, 항공사명·공항명까지 실제로 번역된 값을 받아옵니다. 이 공공 API는 베트남어를 지원하지 않아 베트남어 선택 시에는 영어(E)로 조회합니다.

## 실시간 항공편 데이터 (`server/`)

온보딩 3단계의 "실시간 조회" 버튼은 로컬 프록시 서버를 통해 **공공데이터포털(data.go.kr) 인천국제공항공사 "여객편 운항현황(다국어)" API**(`getPassengerArrivalsOdp`)를 호출해 입력한 항공편의 실제 도착 예정/변경 시각, 항공사, 출발지, 터미널·게이트, 운항 상태를 받아옵니다.

서비스키를 브라우저에 노출하지 않기 위해 Node/Express 프록시를 거칩니다.

### 설정 및 실행

```bash
cd server
npm install
cp .env.example .env
# .env 파일을 열어 AIRPORT_SERVICE_KEY에 발급받은 서비스키를 입력
npm start
```

서버가 `http://localhost:3001`에서 뜹니다. 그 상태에서 `app/index.html`을 열면 온보딩 3단계의 "실시간 조회" 버튼이 동작합니다.

- 서비스키는 data.go.kr 마이페이지 > 활용신청 현황에서 발급받은 "일반 인증키"를 사용합니다. **Encoding/Decoding 어느 버전을 넣어도** 서버에서 자동으로 정규화해서 이중 인코딩 오류 없이 동작합니다.
- 이 API는 **당일(same-day) 운항 항공편만** 조회됩니다. 오늘 실제로 운항하지 않는 편명을 입력하면 "일치하는 항공편이 없어요" 에러가 뜨고, 자동으로 데모 값(10:30 도착 기준)으로 폴백합니다.
- 계산 로직:
  - 도착편만 조회됐을 때: `공항 복귀 추천 시각 = 도착 시각 + 6시간(고정 레이오버 예산)`.
  - 연결편(출발편)까지 조회되면: `공항 복귀 추천 시각 = 연결편 출발 시각 - 90분(탑승 마감 버퍼)`로 바뀝니다. 단, 최소 체류 60분은 보장합니다.
- 프록시 서버를 끄고 앱을 열면 조회 버튼이 실패로 처리되며 기존 데모 값/고정 예산으로 동작합니다(앱 자체가 멈추지는 않습니다).

## 실시간 이동시간 (`server/` — 도보 / 대중교통(ODsay) / 자동차(카카오모빌리티))

코스 빌더에서 데이유즈 숙소를 고르면, 공항→숙소·숙소→(선택한 카테고리의) 각 활동 장소까지 직선거리 기준으로 이동수단을 자동으로 고른 뒤 실제 이동시간을 받아옵니다(`app/index.html`의 `fetchTravelMin`):

- 1.2km 이하 → 도보로 간주, API 호출 없이 시속 4.5km 기준으로 추정 계산
- 6km 이상 → ODsay 대중교통(지하철/버스) API를 먼저 시도. 실패(키 없음·노선 없음)하면 조용히 자동차로 폴백
- 그 사이 → 카카오모빌리티 길찾기(자동차) API

일정 계산(`computeUsed`)·자동 코스 짜기(`autoBuild`)·타임라인 표시가 모두 이 실제 값을 사용하고, 조회에 실패하거나 키가 없으면 조용히 더미 `move` 값(분)으로 되돌아갑니다. 코스 빌더의 각 장소 카드에는 실제로 어떤 수단으로 계산됐는지 도보/전철/자동차 아이콘으로 표시됩니다.

### 설정

```bash
# server/.env 에 아래 값을 추가
KAKAO_REST_API_KEY=발급받은_REST_API_키
ODSAY_API_KEY=발급받은_ODsay_키
```

**카카오모빌리티**
1. [Kakao Developers](https://developers.kakao.com)에 로그인 → **내 애플리케이션** → 앱 생성
2. 생성한 앱 → **앱 키** 탭의 **REST API 키**를 그대로 `KAKAO_REST_API_KEY`에 입력 (Encoding/Decoding 구분 없음)

**ODsay (대중교통)**
1. [ODsay Lab](https://lab.odsay.com)에 회원가입 → API 신청에서 키 발급
2. 발급받은 키를 `ODSAY_API_KEY`에 입력 (비워두면 대중교통 구간도 자동차 값으로 계산됨)

설정 후 `npm start`로 프록시 재기동.

- 구글맵 Directions API 대신 카카오모빌리티를 쓴 이유: 국내 지도 데이터 반출 제한 때문에 구글맵의 국내 도로 경로 정확도가 떨어져서, 인천/영종도 권역 실경로엔 국내 API가 더 정확합니다.
- 카카오모빌리티 좌표는 "경도,위도"(x,y) 순서로 보내야 합니다 — 위경도(lat,lng)와 반대 순서라 헷갈리기 쉽습니다(`server.js`의 `/api/route`에서 이미 처리).
- `/api/transit`(ODsay)의 응답 필드(`result.path[0].info.totalTime`)는 실제 키로 검증하기 전 문서 기준으로 짠 것이라, 실제 응답 스키마가 다르면 `server.js`에서 파싱 부분만 고치면 됩니다 — 파싱 실패 시에도 자동차로 조용히 폴백하므로 앱이 깨지지는 않습니다.
- `ROOMS`/`PLACES`의 좌표는 전부 카카오 지오코딩·장소검색으로 얻은 실제 위치입니다(더미 좌표 아님).

### API 엔드포인트 (프록시)

## 코스 빌더 지도 (`app/index.html` — 카카오맵 JS SDK)

코스 빌더에서 데이유즈 숙소를 고르면 **자동으로**(별도 토글 없이) 목록 위에 카카오맵이 뜨고, 공항·숙소 3곳·전체 카테고리(브랜드 포함)의 모든 장소가 핀으로 표시됩니다. 핀을 탭하면 `toggle()`이 그대로 호출돼서 목록 화면과 동일하게 일정에 추가/제거됩니다. 여기에 더해 숙소 주변의 **실제 카페·음식점**(카카오 로컬 카테고리 검색, `FD6`/`CE7`, 반경 1km)도 작은 회색 점으로 같이 표시됩니다 — 이건 참고용이라 탭하면 이름만 살짝 보여주고 일정에는 추가되지 않습니다.

- 위에서 쓴 **REST API 키**가 아니라 **JavaScript 키**를 씁니다 — JS 키는 원래 프론트엔드 코드에 그대로 노출되는 게 정상입니다(비밀키가 아니라 "이 도메인에서만 쓸 수 있음"으로 보호하는 방식). `app/index.html` `<head>`에 이미 박혀 있습니다.
- **반드시 도메인 등록이 필요합니다.** [Kakao Developers](https://developers.kakao.com) → 내 애플리케이션 → **앱 설정 > 플랫폼 키 > 플랫폼 설정(또는 앱 설정 > 일반의 "플랫폼")** 에서 **Web 플랫폼**에 `http://localhost:3001`을 등록하세요. 등록 전에는(또는 `file://`로 열면) 지도 대신 안내 문구만 뜨고, 나머지 기능은 그대로 동작합니다.
- **"카카오맵" 제품도 별도로 활성화해야 합니다.** 도메인 등록과는 별개 단계로, Kakao Developers → 앱 → 제품 설정 → 카카오맵을 켜야 합니다. 안 켜져 있으면 `NotAuthorizedError`(`disabled OPEN_MAP_AND_LOCAL service`)로 조용히 실패합니다 — 실제 주변 카페/음식점을 가져오는 `/api/places`(카카오 로컬)도 같은 제품에 묶여 있어서 같이 활성화됩니다.
- 그래서 프록시 서버가 `app/`을 같이 정적 서빙하도록 만들었습니다 — `file://`로는 카카오맵이 도메인을 인식 못 하기 때문입니다. 항상 `http://localhost:3001`로 여세요.
- 마커는 별도 이미지 없이 `kakao.maps.CustomOverlay` + 이모지/색상 원으로 그립니다(공항 ✈, 숙소 🏨, 장소는 카테고리 색 원 — 일정에 담긴 장소는 ✓, 실제 주변 가게는 작은 회색 점).

### API 엔드포인트 (프록시) — 카카오 로컬(주변 실제 장소)

`GET http://localhost:3001/api/places?lat=37.4470&lng=126.4460&category=CE7&radius=1000` (카테고리 코드: `FD6`=음식점, `CE7`=카페)

```json
{ "places": [{ "name": "OO커피", "lat": 37.4468, "lng": 126.4472, "category": "음식점 > 카페 > 커피전문점" }] }
```

## 알려진 제한 사항 / 다음 단계 후보

- 숙소·활동 장소 전부 실존 업체(이름·주소·좌표·실제 이동시간)이지만, 요금·영업시간·시간블록·평점은 추정치입니다. 실제 예약 연동은 각 업체와의 제휴 계약이 필요합니다.
- 신라면세점/올리브영/스카이허브라운지 등 일부 업체는 "쇼핑"·"휴식" 카테고리와 "브랜드" 카테고리에 같은 실제 지점이 중복 등록돼 있습니다(다른 관점으로 볼 수 있게 의도적으로 남겨둠).
- 코스 빌더는 각 장소의 "숙소→장소" 이동시간만 실측하고, 장소↔장소 간 실제 동선(방문 순서 최적화)은 아직 계산하지 않습니다. 필요하면 카카오모빌리티 다중경유지 API나 간단한 nearest-neighbor 정렬을 추가할 수 있습니다.
- 도보/대중교통/자동차 분기는 순수 직선거리 임계값(1.2km / 6km)으로만 판단합니다 — 실제로 그 구간에 대중교통이 다니는지는 확인하지 않고 ODsay 응답 성공 여부로만 판단합니다.
- `ODSAY_API_KEY`는 아직 실제 키로 응답 스키마를 검증하지 못했습니다. 키를 발급받으면 `/api/transit`을 한 번 호출해서 실제 필드명이 `server.js`의 가정과 맞는지 확인이 필요합니다.
- "브랜드" 카테고리(올리브영/프리미엄 라운지)와 "쇼핑"/"휴식" 카테고리의 일부 항목이 같은 실제 브랜드를 가리키는 별개의 더미 항목으로 중복돼 있습니다(id는 다름). 프로토타입이라 의도적으로 정리하지 않았습니다.
- 카카오맵 도메인(`http://localhost:3001`)을 등록하기 전까지는 지도 보기가 안내 문구만 보여줍니다 — 위 "코스 빌더 지도" 섹션 참고.
- 로컬 프록시 서버(`localhost:3001`)가 켜져 있어야 실시간 조회가 동작합니다. 배포 시에는 프록시를 실제 서버(예: Vercel Functions, Cloud Run 등)로 옮기고 프론트엔드의 `PROXY_BASE` 값을 바꿔야 합니다.
- `server/.env`는 서비스키가 담겨 있으므로 `server/.gitignore`에 의해 git에 커밋되지 않습니다. 저장소를 공유/배포할 때는 `.env.example`만 커밋되어 있는지 다시 확인하세요.
