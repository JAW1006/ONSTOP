# B1 호텔 복귀 경로 — 의도한 변경 기록

> 상태: 확정 · 2026-10-16 · 공식: [time-fit](../formulas/time-fit.md) "B1" · 명세: [screens/course-map](../design/screens/course-map.md), [screens/booking](../design/screens/booking.md)

## 목표

코스 경로를 **공항 → 호텔 → 장소들 → 호텔(짐 찾기) → 공항**으로 바꾼 변경(B1, 2026-10-16 사용자 결정)이 숫자를 어떻게 바꾸는지 기록한다. 이 변경은 **의도한 변경**이며 이식 오류가 아니다.

배경: 데이유즈 상품에 "짐보관"이 포함돼 있어, 장소를 돈 뒤 짐을 찾으러 호텔에 돌아와야 한다. 기존 순차 경로(A6)는 마지막 장소에서 공항으로 바로 가서 이 이동을 빠뜨렸다.

## 방법

- domain: [`time-fit-sequential.test.ts`](../../src/domain/time-fit-sequential.test.ts) 예시 S1–S6을 새 공식으로 다시 계산(공식 md와 같은 숫자).
- 화면: [`CourseScreen.test.tsx`](../../src/features/course/CourseScreen.test.tsx)의 같은 입력(KE085 도착 10:30, 호텔 오라, 모의 경로 API)을 바꾸기 전과 후로 비교.

## 결론

- **코스 가용 시간(외출 가능 − 준비 20분)은 그대로**다. 바뀌는 것은 **코스 사용 시간**이다. 장소가 있으면 "마지막 장소 → 호텔" 이동이 더해지고, 공항 복귀는 언제나 호텔에서 출발한다. 그래서 같은 가용 시간 안에 담을 수 있는 장소·체류가 줄어든다.
- 그 결과 **"환승 내 가능" 판정과 자동 추천이 더 보수적으로** 바뀐다. 전에는 들어가던 장소가 빠지거나, 여유가 초과로 바뀔 수 있다. 위 저장된 코스는 여유 3분에서 7분 초과로 바뀌었다.
- 호텔이 공항과 장소 사이에 있지 않으면(장소가 공항 반대편 등) 차이가 커진다. 호텔이 공항과 가까울수록 차이가 작다.
- 데이유즈 블록을 고르면 **호텔 복귀 ≤ 블록 종료**도 제약이 된다. 넘으면 경고하고, 마지막 장소 출발 기한을 블록 종료 기준으로 당긴다. 자동 추천과 "환승 내 가능"도 이 제약을 넘는 장소를 빼고 판정한다.
- 호텔에 다시 머무는 시간(짐 찾기·샤워)은 0분으로 둔다. 기존의 "숙소 체류는 넣지 않는다" 규칙을 그대로 유지했다.
