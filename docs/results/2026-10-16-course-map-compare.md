# 코스 지도 이식 — 레거시 비교

> 상태: 확정 · 2026-10-16 · 명세: [screens/course-map](../design/screens/course-map.md) · 공식: [time-fit](../formulas/time-fit.md)

## 목표

1. 레거시 코스 계산을 옮긴 함수(별 모양)가 **레거시 화면과 같은지**(이식 오류 확인 — STATUS "검증 부족" 항목)
2. 같은 입력에서 레거시와 새 코스 화면이 어떻게 다른지, 그 차이를 **의도한 변경**과 **이식 오류 가능성**으로 나눈다.

## 방법

- 임시 모의 API(실제 키 미사용, 결과 고정): 자동차 = 직선 1km당 2분(거리 ×1.3), 대중교통 = 1km당 3분(거리 ×1.4, 버스1+지하철1, 1,500원), 도보(≤1.2km)는 두 앱 모두 자체 추정. 주변 실시간 장소는 0개.
- headless Chrome으로 **두 앱을 같은 순서로 조작**: 한국어 → 항공편(도착 KE085 10:30, T1) → 스마트 코스 추천 → 코스 탭 → 호텔 오라 선택 → 장소 추가 또는 자동 추천 → 화면 글자를 그대로 읽음.
- 항공편 3종: **충분** LONG1 19:00 · **빠듯** MID1 14:51 · **짧음** SHORT1 14:10(출발, 탑승동). 장소: **0개**, **1개**(롯데하이마트), **여러 개**(하이마트·올리브영·다이소), **자동 추천**(관심사 쇼핑·휴식, 선택 카테고리 쇼핑).
- 모의 규칙에서 나온 구간(분): 공항↔호텔 오라 6(자동차) · 호텔→하이마트 23·올리브영 24·다이소 24(대중교통) · 하이마트→올리브영 도보 2 · 올리브영→다이소 도보 3 · 하이마트→공항 19 · 올리브영→공항 19 · 다이소→공항 20.

## 수치

### 1) 이식 확인 — 레거시 화면 = 옮긴 레거시 함수

| 경우         | 레거시 화면(관측)                                                                         | 레거시 함수(`courseUsedMin`+준비, `buildCourseTimeline`, `autoBuild`) |
| ------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 장소 0개     | 총 0시간 32분, 체크인 10:56, 복귀 11:02                                                   | 32, 10:56, 11:02 ✅                                                   |
| 하이마트 1곳 | 총 2시간 12분(= 20+6+23+60+**23**), 도착 11:19, 복귀 12:42                                | 132, 11:19, 12:42 ✅                                                  |
| 3곳          | 총 4시간 1분(= 20+6+(23+60)+(**24**+30)+(**24**+30)+**24**), 12:43·13:37 도착, 복귀 14:31 | 241, 12:43·13:37, 14:31 ✅                                            |
| 자동 추천    | 올리브영 1곳, 총 1시간 44분(예산 140·181·430 모두)                                        | 올리브영, 104 ✅                                                      |

→ 별 모양 계산 이식은 **레거시 화면과 일치**. 이 값들을 [`time-fit.test.ts`](../../src/domain/time-fit.test.ts) "레거시 화면 관측값"으로 고정했다.

### 2) 레거시 vs 새 화면 (같은 입력)

"사용"은 준비 20분 포함. 레거시 예산 = 복귀 추천 − 도착, 새 화면 가용 = 외출 가능 시간(입국심사 50분 뒤부터).

| 항공편     | 장소 | 레거시: 사용 / 예산 → 여유·초과 | 새 화면: 사용 / 가용 → 여유·초과                                       | 차이 원인                                                        |
| ---------- | ---- | ------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 충분 19:00 | 0    | 32 / 430 → 여유 398             | 32 / 380 → 여유 348                                                    | 가용 −50(A1)                                                     |
| 충분       | 1    | 132 / 430 → 여유 298            | 128 / 380 → 여유 252                                                   | 사용 −4(A6 복귀 19 vs 23), 가용 −50                              |
| 충분       | 3    | 241 / 430 → 여유 189            | 194 / 380 → 여유 186                                                   | 사용 −47(A6: 장소 간 도보 2·3 vs 24·24, 복귀 20 vs 24), 가용 −50 |
| 충분       | 자동 | 올리브영, 104 → 여유 326        | 올리브영, 99 → 여유 281                                                | 같은 장소 선택. 사용 −5(A6 복귀)                                 |
| 빠듯 14:51 | 0    | 32 / 181 → 여유 149             | 32 / 131 → 여유 99                                                     | A1                                                               |
| 빠듯       | 1    | 132 / 181 → 여유 49             | 128 / 131 → **여유 3**                                                 | A1 + A6                                                          |
| 빠듯       | 3    | 241 / 181 → **60분 초과**       | 194 / 131 → **63분 초과**, 경고 + 복귀 예상 14:34(목표 13:31보다 늦음) | A1 + A6. 새 화면만 늦음 시각 표시                                |
| 빠듯       | 자동 | 올리브영, 104 → 여유 77         | 올리브영, 99 → 여유 32                                                 | A1 + A6                                                          |
| 짧음 14:10 | 0    | 32 / 140 → 여유 108             | 32 / 90 → 여유 58                                                      | A1                                                               |
| 짧음       | 1    | 132 / 140 → **여유 8**          | 128 / 90 → **38분 초과**, 복귀 예상 13:28 > 12:50                      | A1(레거시에선 들어가던 코스가 초과)                              |
| 짧음       | 3    | 241 / 140 → 101분 초과          | 194 / 90 → 104분 초과                                                  | A1 + A6                                                          |
| 짧음       | 자동 | **올리브영 1곳**, 104 → 여유 36 | **0곳**(아무것도 안 담김)                                              | A1: 가용 70분에 올리브영(실제 79분)이 안 들어감                  |

시각: 새 화면은 모든 일정이 **50분 늦게 시작**(공항 밖 11:20, 체크인 11:46 — 레거시 10:30·10:56). 복귀 추천 시각은 같음(13:31 등).

### 이식 오류 가능성

| #      | 내용                                                                                                                                                                                                                                 | 판단                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| —      | 비교한 12개 조합에서 **설명 안 되는 숫자 차이는 없었다**. 별 모양 함수는 레거시 화면과 값이 같고, 새 화면 값은 순차 경로 공식으로 손계산한 값과 같다.                                                                                | 발견 없음                                                       |
| 주의 1 | 자동 추천·"환승 내 가능" 판정은 아직 조회 안 한 구간을 **근사값**(직선 1km당 2분)으로 쓴다. 대중교통이 근사보다 느리면(실제 ODsay 호텔 오라→차이나타운 95분 vs 근사 약 36분) 추천 직후 실제 구간이 들어오며 **초과로 바뀔 수 있다**. | 설계상 한계 — STATUS 개선 후보                                  |
| 주의 2 | 자동 추천이 0곳일 때 안내 문구가 없다(레거시도 같음).                                                                                                                                                                                | STATUS 개선 후보                                                |
| 미확인 | 실제 카카오맵 화면(핀·칩·선 모양·선택 강조)은 모의 지도로만 테스트했다.                                                                                                                                                              | 사용자 확인 절차 — [STATUS](../STATUS.md) "실제 지도 확인 절차" |
