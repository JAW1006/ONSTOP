# Time-Safe(온보딩) 화면 이식 — 레거시 비교

> 상태: 확정 · 2026-10-16 · 명세: [screens/time-safe](../design/screens/time-safe.md) · 공식: [time-safe](../formulas/time-safe.md)

## 목표
레거시 `Onboarding` 3단계를 React 화면으로 옮기고, 같은 입력에서 레거시와 같은 결과(결정된 변경만 차이)가 나오는지 확인한다.

## 방법
1. **자동 테스트** — [`OnboardingScreen.test.tsx`](../../src/features/time-safe/OnboardingScreen.test.tsx): 실제 라우트·QueryClient로 화면을 렌더하고 `fetch`를 모의 응답으로 바꿔 단계 이동·조회·결과·CTA·오류를 확인(8건).
2. **나란히 비교** — 임시 모의 API 서버(실제 키 미사용)가 같은 항공편 데이터를 주도록 하고, 레거시(`app/index.html`)와 새 화면을 headless Chrome으로 같은 순서(한국어 → 다음 → 다음 → 두 편명 조회)로 조작해 결과 카드 텍스트와 스크린샷을 비교.
3. 실제 인천공항 API로는 비교하지 않았다(서버 키 없음) → [STATUS](../STATUS.md) API 형식 항목과 함께 5단계에서.

## 수치 — 같은 입력, 결과 카드 비교
| 입력 | 레거시 | 새 화면 | 차이 원인 |
|---|---|---|---|
| 도착 10:30(KE085, T2) → 출발 14:51(MU2043, T2) | 총 4시간 21분, **3시간 1분**, 도착 10:30 · 복귀 13:31 | 총 4시간 21분, **2시간 11분**, 도착 10:30 · 복귀 13:31, 버퍼 구성 줄 | 입국심사 버퍼 50분(A1 기본값). 복귀 시각은 같음 |
| 도착 22:00(NIGHT1) → 출발 01:30(NIGHT2) | 출발 "01:30", 총 **"-21시간 -30분"**, **외출 불가** | 출발 "**익일** 01:30", 총 3시간 30분, **1시간 20분**, 복귀 익일 00:10 | A2 자정 넘김 수정 |

항공편 줄(항공사·편명·출발지·터미널·게이트·상태)과 연결편 줄은 두 입력 모두 글자까지 같았다.

### 자동 테스트 (8건, 모두 통과)
| 시나리오 | 확인 내용 |
|---|---|
| 언어 → 관심사 → 항공편 | 한국어 전환 즉시 문구 변경, 기본 관심사(쇼핑·휴식) 선택·토글 |
| #1 낮 사례 | 2h 11m, 총 4h 21m, 복귀 13:31, 버퍼 구성 줄, CTA → `/` 이동 |
| #6 야간 | 익일 01:30, 1h 20m, 복귀 익일 00:10 |
| #3 시간 부족 | 외출 불가 박스, CTA는 활성(레거시와 같음) |
| #12 T1 연결편 | `/api/security-wait` 호출, 평균 65분 → 1h 56m |
| T2 연결편 | 출국장 대기 조회 안 함 |
| 404 | "일치하는 항공편이 없어요 · 재조회 안내" |
| 입력 | 대문자 변환, 빈 칸이면 조회 버튼 비활성 |

## 결론
- 결과 카드는 **결정된 변경(A1 입국심사 50분, A2 자정 넘김)만큼만** 레거시와 다르다.
- 화면 차이(의도): 태그라인 26→22px(타이포 스케일), 버퍼 구성 줄 추가, 경고 줄(24h 초과·출발 선행), 404 번역, 기본 편명 제거, `?step=` URL.
- 레거시와 같은 동작으로 둔 것: 새로 고침 시 언어·입력 초기화(저장 안 함).
- **후속 변경(2026-10-16, 같은 날):** 외출 불가면 CTA 비활성 + 이유 문구(레거시는 활성), 버퍼 구성 줄에 "예상/약" 표기. 테스트 #3 기대값을 바꿨다.
