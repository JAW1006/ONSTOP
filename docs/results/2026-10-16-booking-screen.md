# 데이유즈 예약 화면 이식 — 레거시 비교

> 상태: 확정 · 2026-10-16 · 명세: [screens/booking](../design/screens/booking.md) · 공식: [dayuse-pricing](../formulas/dayuse-pricing.md), [time-fit](../formulas/time-fit.md)

## 목표
레거시 `Booking`·`Confirm`과 새 예약 화면이 같은 입력에서 어떻게 다른지 기록한다. 차이마다 **의도한 변경**인지 확인한다.

## 방법
- 같은 입력: 도착 KE085 10:30(T1), 출발 MU2043 14:51(탑승동), 숙소 호텔 오라. 레거시 이동시간은 데이터 `move` 16분이고, 새 화면은 근사 19분 또는 저장된 코스의 실제 경로다.
- 레거시 값: 레거시 코드의 식으로 계산했다(domain에 남긴 레거시 비교용 함수 `roomHourTiers`·`checkInSlots`·`defaultTier`, 테스트 고정).
- 새 화면 값: [`BookingScreen.test.tsx`](../../src/features/booking/BookingScreen.test.tsx)(모의 API, **가상의 가격표** — 실제 호텔 가격 아님).
- headless 브라우저로 두 화면을 나란히 비교하지는 않았다. 새 화면은 흐름(요청 → 호텔 확인)과 가격 출처가 달라 같은 조작으로 비교할 수 없다.

## 수치
| 항목 | 레거시 | 새 화면 | 차이 원인 |
|---|---|---|---|
| 가장 이른 체크인 | 10:30 + 20 + 16 = **11:06** | 공항 밖 11:20 + 20 + 근사 19 = **11:59**(코스 없음) / 저장된 코스(하이마트) 실제 6분 → 11:46 | A5(입국심사 버퍼 50분), A10(코스 기준 이동시간) |
| 체크인 후보 | 11:30부터 6개 | 12:00부터 6개 | 위와 같음 |
| 상품·가격 | 3–9h, 50,000 + 8,000/h(계산식) | 호텔 가격표 그대로. 지금 데이터에 가격표가 없어 **모든 숙소가 견적 요청**(데모 가격표 파일도 비어 있음) | A9 |
| 기본 상품 | 슬롯 11:30, 남는 121분 → 들어가는 상품 없음 → 3h | 같은 규칙. 가상의 가격표(1h 포함), 슬롯 12:00이면 1h | 규칙 유지 |
| 경고 | 체크아웃 14:30 > 복귀 추천 13:31 → "체크아웃이 복귀 추천 시각 이후" | 하이마트 코스 + 1h: **숙소 복귀 13:46 > 이용 종료 13:00(46분)** + 공항 복귀 13:52 > 목표 13:31(21분) → 확인 체크해야 요청 가능 | B1·B3 |

| 연락처 | 없음 | 이름(영문 가능)·이메일 + 확인, 동의 3개 | ADR-0003, B4 |
| 데모 아닌 빌드 | — | 요청 버튼 비활성 + "준비 중", 참여 확정 호텔만 노출(지금 데이터 기준 0곳) | B6, 운영 배포 금지 조건 |

## 결론
- 레거시와 다른 값은 모두 위 결정(A5·A9·A10·B1·B3·B4·B6)으로 설명된다. 이식 오류로 보이는 차이는 없었다.
- **지금 데이터로는 상품 요청 모드가 나오지 않는다.** 호텔 가격표와 데모 가격표가 모두 비어 있어서, 데모에서도 모든 숙소가 견적 요청으로 나온다. 상품 요청 흐름은 가상의 가격표로 테스트에서만 확인했다.
- 공항에서 먼 숙소(웨스턴그레이스, 근사 75분)는 #1 항공편에서 숙소 출발 기한이 체크인보다 이르다. 그래서 "이용할 시간이 남지 않아요"를 보여주고 요청을 막는다(명세에 없던 경우라 추가했다).
