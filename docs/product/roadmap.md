# 로드맵 — 공모전 프로토타입에서 실제 서비스로

> 상태: 초안 · 최종 수정 2026-10-16 · 진행 상태는 [STATUS](../STATUS.md), 결정 기록은 [decisions/](../decisions/)
> 기간·인원은 아직 정하지 않았다. 단계는 **순서**만 뜻한다(앞 단계가 끝나야 다음 단계 공개 가능).

## 현재 위치 (2026-10-16)
| 영역 | 상태 |
|---|---|
| 화면 | Time-Safe(온보딩)·홈·코스 지도 이식 완료. 데이유즈 예약·짐 케어·마이 남음 |
| 계산 | domain 순수 함수 + 테스트(144개), 공식 md가 단일 출처 |
| 서버 | Express 프록시 1개(JS), 키는 `server/.env`, Render 무료 웹 서비스 1개 |
| 데이터 | 숙소 10·장소 22 정적 JSON, 가격·체류·평점 **미검증** — [data-verification](../design/data-verification.md) |
| 저장 | 없음(새로 고침하면 예약·코스 사라짐) |
| 결제·인증·알림 | 없음(결제 화면은 데모) |

## 남은 화면 이식 순서 (제안)
| 순서 | 화면 | 이유 | 선행 조건 |
|---|---|---|---|
| 1 | **데이유즈 예약**(`/booking/:roomId`, `/bookings`) | 수익 모델의 핵심(데이유즈 12%). 코스 → "이 숙소로 예약하기"가 지금 빈 화면으로 끊긴다. 계산(타임블록 가격·체크인 슬롯)은 이미 domain에 있음 | A9(시간 범위·추가 시간 가격 규칙) 결정. 결제는 데모 유지 가능 |
| 2 | **마이** | 예약 내역·언어 설정을 보여줄 곳. 예약을 옮기면 바로 필요. 알림 토글은 삭제됨 | 예약 이식 |
| 3 | **짐 케어** | 지금은 옵션 3개·가격 표시뿐인 정적 안내. 제휴(보관·배송 업체) 전까지는 기능이 없다 | 제휴 범위 결정 전이면 안내 화면으로만 |

이 순서는 4단계 마무리이며, 끝나면 5단계(레거시 비교 후 `legacy/` 이동)로 간다.

## 서버 TS 전환·모노레포 계획 (화면 이식이 끝난 뒤)
| 순서 | 작업 | 내용 | 위험도 | 위험 줄이는 방법 |
|---|---|---|---|---|
| 1 | 레거시 이동(5단계) | `app/` → `legacy/`, 서버의 `app/` 정적 서빙 제거 또는 `legacy/`로 경로 변경 | **중** — 지금 배포(Render)가 서버에서 `app/`을 서빙한다 | staging에서 먼저, 레거시 접속 경로 공지 |
| 2 | 서버 응답 계약 고정 | 각 `/api/*` 실제 응답을 녹화(키 제거)해 계약 테스트로 고정 | 낮음 | 지금 문서화된 샘플(`docs/api/`) 재사용 |
| 3 | 서버 TS 전환 | `server.js` → `src/*.ts`(라우트별 파일), 같은 동작 유지, `tsx`/`tsc` 빌드 | **중** — 런타임 변화(ESM, fetch 타입), 빌드 단계가 새로 생김 | 2의 계약 테스트 통과가 조건. 동작 변경 금지(리팩터링만) |
| 4 | 모노레포 정리 | `apps/web`(현재 루트) · `apps/server` · `packages/domain`(공식) · `packages/api-types`(응답 타입), npm workspaces | **높음** — 경로 별칭, Vitest·tsconfig 참조, Render `rootDir`·빌드 명령이 모두 바뀜 | 한 번에 하지 않고 ①server 이동 ②web 이동 ③공유 패키지 추출 순으로 커밋 분리, 각 단계 staging 배포 확인 |
| 5 | 공유 타입 적용 | 프런트 `api.ts`와 서버가 같은 응답 타입 사용 | 낮음 | 타입만, 런타임 변화 없음 |
| 6 | Render 설정 변경 | 정적 사이트 + API 서비스 분리, 환경별 서비스 | **높음** — 배포 중단 가능 | [ADR-0005](../decisions/ADR-0005-environments-deploy.md) 순서대로, `main` 자동 배포는 마지막에 전환 |

전제: 이 작업 동안 기능 추가 금지(동작 동일). 각 단계 끝에 전체 테스트 + staging 수동 확인.
