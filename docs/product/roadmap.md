# 로드맵 — 공모전 프로토타입에서 실제 서비스로

> 상태: 초안 · 최종 수정 2026-10-16 · 진행 상태는 [STATUS](../STATUS.md), 결정 기록은 [decisions/](../decisions/)
> 기간·인원은 아직 정하지 않았다. 단계는 **순서**만 뜻한다(앞 단계가 끝나야 다음 단계 공개 가능).

## 현재 위치 (2026-10-16)

| 영역           | 상태                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| 화면           | Time-Safe(온보딩)·홈·코스 지도 이식 완료. 데이유즈 예약·짐 케어·마이 남음                                  |
| 계산           | domain 순수 함수 + 테스트(146개), 공식 md가 단일 출처                                                      |
| 서버           | Express 프록시 1개(JS), 키는 `server/.env`, Render 무료 웹 서비스 1개                                      |
| 데이터         | 숙소 10·장소 22 정적 JSON, 가격·체류·평점 **미검증** — [data-verification](../design/data-verification.md) |
| 저장           | 없음(새로 고침하면 예약·코스 사라짐)                                                                       |
| 결제·인증·알림 | 없음(결제 화면은 데모)                                                                                     |

## 남은 화면 이식 순서 (제안)

| 순서 | 화면                                               | 이유                                                                                                                                        | 선행 조건                                                                                                                                                  |
| ---- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | **데이유즈 예약**(`/booking/:roomId`, `/bookings`) | 수익 모델의 핵심(데이유즈 12%). 코스 → "이 숙소로 예약하기"가 지금 빈 화면으로 끊긴다. 계산(타임블록 가격·체크인 슬롯)은 이미 domain에 있음 | A9 결정됨(호텔별 실제 판매 블록·가격표, [dayuse-pricing](../formulas/dayuse-pricing.md)) — 값은 인터뷰로 입력. 첫 예약은 결제 없이 "예약 요청 → 호텔 확인" |
| 2    | **마이**                                           | 예약 내역·언어 설정을 보여줄 곳. 예약을 옮기면 바로 필요. 알림 토글은 삭제됨                                                                | 예약 이식                                                                                                                                                  |
| 3    | **짐 케어**                                        | 지금은 옵션 3개·가격 표시뿐인 정적 안내. 제휴(보관·배송 업체) 전까지는 기능이 없다                                                          | 제휴 범위 결정 전이면 안내 화면으로만                                                                                                                      |

이 순서는 4단계 마무리이며, 끝나면 5단계(레거시 비교 후 `legacy/` 이동)로 간다.

## 서버 TS 전환·모노레포 계획 (화면 이식이 끝난 뒤)

| 순서 | 작업                | 내용                                                                                                                                                   | 위험도                                                                             | 위험 줄이는 방법                                                                                       |
| ---- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1    | 레거시 이동(5단계)  | `app/` → `legacy/`, 서버의 `app/` 정적 서빙 제거 또는 `legacy/`로 경로 변경                                                                            | **중** — 지금 배포(Render)가 서버에서 `app/`을 서빙한다                            | staging에서 먼저, 레거시 접속 경로 공지                                                                |
| 2    | 서버 응답 계약 고정 | 각 `/api/*` 실제 응답을 녹화(키 제거)해 계약 테스트로 고정                                                                                             | 낮음                                                                               | 지금 문서화된 샘플(`docs/api/`) 재사용                                                                 |
| 3    | 서버 TS 전환        | `server.js` → `src/*.ts`(라우트별 파일), 같은 동작 유지, `tsx`/`tsc` 빌드                                                                              | **중** — 런타임 변화(ESM, fetch 타입), 빌드 단계가 새로 생김                       | 2의 계약 테스트 통과가 조건. 동작 변경 금지(리팩터링만)                                                |
| 4    | 모노레포 정리       | `apps/web`(현재 루트) · `apps/server` · **`apps/mobile`(자리만, 아래 C1)** · `packages/domain`(공식) · `packages/api-types`(응답 타입), npm workspaces | **높음** — 경로 별칭, Vitest·tsconfig 참조, Render `rootDir`·빌드 명령이 모두 바뀜 | 한 번에 하지 않고 ①server 이동 ②web 이동 ③공유 패키지 추출 순으로 커밋 분리, 각 단계 staging 배포 확인 |
| 5    | 공유 타입 적용      | 프런트 `api.ts`와 서버가 같은 응답 타입 사용                                                                                                           | 낮음                                                                               | 타입만, 런타임 변화 없음                                                                               |
| 6    | Render 설정 변경    | 정적 사이트 + API 서비스 분리, 환경별 서비스                                                                                                           | **높음** — 배포 중단 가능                                                          | [ADR-0005](../decisions/ADR-0005-environments-deploy.md) 순서대로, `main` 자동 배포는 마지막에 전환    |

전제: 이 작업 동안 기능 추가 금지(동작 동일). 각 단계 끝에 전체 테스트 + staging 수동 확인.

### 앱 전환(Capacitor) 대비 — 같은 계획에 포함 (2026-10-16 추가)

웹 빌드를 그대로 감싸 iOS·Android 앱으로 내는 것을 전제로, **지금 구조가 앱에서 깨지지 않게** 미리 정리한다(앱 출시는 별도 결정).

| 순서 | 작업                                 | 내용                                                                                                                                                                                                                                                                                   | 위험도 | 위험 줄이는 방법                                                           |
| ---- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------- |
| C1   | `apps/mobile` 자리 확보              | 모노레포 4단계에서 빈 패키지(README·설정 자리만). 웹 빌드(`apps/web/dist`)를 그대로 쓰는 구조                                                                                                                                                                                          | 낮음   | 실제 Capacitor 설치는 앱 출시 결정 후                                      |
| C2   | **서버 주소 환경변수화**             | 지금 `/api`를 상대 경로로 직접 부르는 곳 **6곳**(`features/time-safe/api.ts` 2곳, `features/course/api.ts` 4곳) → `src/lib/api-url.ts`의 `apiUrl(path)` 하나로 모으고 `VITE_API_BASE`(비어 있으면 같은 출처)로 주소 지정. 앱에서는 출처가 웹 서버가 아니라 상대 경로가 동작하지 않는다 | 낮음   | 기본값이 같은 출처라 웹 동작 변화 없음, 테스트로 확인                      |
| C3   | 서버 CORS                            | 앱 출처(Capacitor WebView 출처 — 정확한 값 **미확인**)와 staging·prod 프런트 도메인 허용                                                                                                                                                                                               | 중     | 허용 목록을 환경변수로                                                     |
| C4   | **브라우저 저장소 접근을 한 곳으로** | 지금은 저장소를 쓰지 않는다(상태가 메모리에만 있음). 앞으로 언어·저장된 코스·예약 요청을 기기에 남길 때 **`src/lib/storage.ts`(비동기 get/set/remove)만** 거치게 규칙화 — 웹은 localStorage, 앱은 기기 저장소로 교체                                                                   | 낮음   | CLAUDE.md 규칙 + `localStorage` 직접 사용을 찾는 검사(린트·grep)           |
| C5   | `window`·`document` 직접 접근 정리   | 지금 4곳(포털 컨테이너, 카카오맵 SDK 로딩, 지도 토큰 읽기, 진입점) — 앱 WebView에서도 동작하지만 SDK 로딩은 확인 필요                                                                                                                                                                  | 중     | 카카오맵 JS SDK의 앱 WebView 도메인 등록 방식 **미확인** — 앱 결정 시 확인 |
| C6   | 알림 이동 경로                       | 앱 출시 때 "기기 내 예약 알림"으로 옮길 수 있게 알림 기능을 `features/alerts`로 분리([ADR-0006](../decisions/ADR-0006-return-alert.md))                                                                                                                                                | 낮음   | 웹은 캘린더 파일, 앱은 기기 알림 — 같은 인터페이스                         |
