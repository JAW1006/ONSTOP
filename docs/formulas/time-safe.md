> 코드: [`src/domain/time-safe.ts`](../../src/domain/time-safe.ts) · 테스트: [`time-safe.test.ts`](../../src/domain/time-safe.test.ts) · 상수: [`constants.ts`](../../src/domain/constants.ts) · 용어: [GLOSSARY](../GLOSSARY.md)

## 정의

### 기존 동작 (레거시 `app/index.html` 361–365, 564–566줄)
```
securityMin = (연결편 터미널 == P01 && 실시간 평균 있음) ? 실시간 평균 : 50
bufferMin   = securityMin + 30

연결편 없음 → returnBy = arrive + LAYOVER_BUDGET, canGoOut = true
연결편 있음 → canGoOut = (depart − bufferMin − arrive) ≥ MIN_STAY
              returnBy  = canGoOut ? depart − bufferMin : arrive
stayMin = returnBy − arrive          (홈·온보딩 표시값)
```
- 도착 = 실시간 예상 우선. 출발 = 실시간 예상 우선, 예정보다 이르면 예정.
- 시각은 `HHMM`만 파싱. 날짜·자정 넘김 처리 없음.
- 도착 후 입국심사 시간 없음. 준비 20분(`PREP`)은 코스 쪽에서만 차감.

### 결정된 공식 (2026-10-16 결정, 이슈별 커밋으로 적용)
| 이슈 | 결정 | 적용 |
|---|---|---|
| A2 자정 넘김 | 날짜가 있으면 날짜로, 없을 때만 출발 < 도착이면 다음 날. 24시간 초과는 경고. | **적용** |
| A3 출국장 실시간 대기 | 대체하지 않고 `max(DEPARTURE_SECURITY_MIN, 실시간)`. 2026-10-16부터 **T1·T2** 모두(T2 API 연동) | **적용** |
| A1 버퍼 구성 | ① 입국심사 / ② 출국 보안검색·출국심사 / ③ 게이트 여유 **3요소 구조 확정**. 값은 미검증, 보수적 기본값 50/50/30. | **적용** (값 미검증) |
| A5 용어 | 외출 가능 시간(Time-Safe 결과) / 코스 가용 시간(= 외출 가능 − 준비). 준비는 Time-Safe에 넣지 않음. | **적용** |

#### 현재 공식 (`computeTimeSafe`)
```
① arrivalImmigration = ARRIVAL_IMMIGRATION_MIN
② security           = (연결편 T1 && 실시간 있음) ? max(DEPARTURE_SECURITY_MIN, 실시간) : DEPARTURE_SECURITY_MIN
③ gateMargin         = GATE_MARGIN_MIN

exitAt       = arrive + ①                       (공항 밖으로 나가는 시각)
returnBuffer = ② + ③

연결편 없음 → returnBy = arrive + LAYOVER_BUDGET, canGoOut = true
연결편 있음 → canGoOut = (depart − returnBuffer − exitAt) ≥ MIN_STAY
              returnBy  = canGoOut ? depart − returnBuffer : exitAt

외출 가능 시간 outing = max(0, returnBy − exitAt)      ← 홈·온보딩 표시
(코스 가용 시간 = outing − COURSE_PREP_MIN → time-fit.md)
```

#### A2 — 시각 정규화 (`resolveConnection`)
```
시각 문자열: "YYYYMMDDHHMM" → 날짜 있음 / "HHMM" → 날짜 없음 (시 ≥ 24, 분 ≥ 60, 없는 날짜는 파싱 실패)
모든 시각 = 도착일 0시 기준 분 (익일이면 1440 이상)

도착·출발 둘 다 날짜 있음 → depart = (출발일 − 도착일) × 1440 + 출발 시각
하나라도 없음          → depart = 출발 시각, 단 출발 < 도착이면 + 1440

예정 vs 예상 비교(출발 조기 보정·지연 표시):
  둘 다 날짜 있음 → 날짜로 차이 계산
  아니면          → 12시간 이내의 가장 가까운 차이 (23:50 → 00:10 = +20분)

경고: depart − arrive > 1440 → OVER_24H,  < 0 → DEPART_BEFORE_ARRIVAL (외출 불가로 계산됨)
```
공항 API는 **날짜 없이 `HHMM`만 준다**(2026-10-16 실제 호출로 확인 — [docs/api/incheon-flights](../api/incheon-flights.md)). 날짜 형식(`YYYYMMDDHHMM`)도 받도록 남겨 둔다(주간 운항 API 등 다른 출처 대비).

#### A3 — 보안검색·출국심사 하한
- "실시간 반영" 표시 = 실시간 평균 > `DEPARTURE_SECURITY_MIN`일 때만 (`isLiveSecurityApplied`).
- 대상: 연결편 터미널 `P01`·`P02`(탑승동) → `/api/security-wait`(T1), `P03` → `/api/security-wait/t2`(T2). 그 외는 기준값.
- 실시간 값의 한계: 조회 시점의 **그 터미널 전체 게이트 평균**이다. 승객이 실제로 지날 출국장 게이트, 복귀하는 시점의 대기, 출국심사 시간을 반영하지 않는다. 그래서 하한으로만 쓴다.

## 엣지 케이스
| 상황 | 처리 |
|---|---|
| 자정 넘김 | 기존: 처리 안 됨(#6, #8) → 현재: A2 규칙 |
| 날짜 없이 24시간 넘는 연결 | 구분 불가 — 출발이 도착보다 늦으면 같은 날로 본다(경고 없음) |
| 실시간 평균이 기준값보다 작음 | 기존: 대체되어 버퍼 감소(#5) → 현재: 기준값 유지(A3) |
| 탑승동(`P02`) 연결편 | 출국 수속을 T1 출국장에서 하므로 **T1 실시간 대기 적용**(2026-10-16 결정). T1 → 탑승동 셔틀트레인 이동·대기 시간은 버퍼에 없음 — 근거 미검증([STATUS](../STATUS.md)) |
| 항공편 API 시각 형식 | 2026-10-16 실제 호출(도착 1,201·출발 1,217건)로 **전부 `HHMM`(날짜 없음)** 확인 → A2의 "날짜로 계산" 경로와 OVER_24H 경고는 현재 API로는 쓰이지 않는다. 예정·예상이 자정을 사이에 두는 출발편 7건 존재(예: 00:05 → 23:55) — 최근접 차이 규칙으로 처리 |
| T2(`P03`) 연결편 | 실시간 없음, 기준값 |
| 출국장 대기 API의 한계 | 조회 시점의 T1 전체 게이트 평균. 하한 방식이라 버퍼를 늘리는 쪽으로만 작동 |
| 연결편 없음 | 복귀 = 도착 + 360, 외출 가능 = 360 − ① |
| 입국 대기 실시간 반영 | 분 단위 공개 API 없음 → 고정값 사용([조사](../results/2026-10-16-arrival-wait-data.md)) |
| 외출 불가 | 복귀 = 공항 밖 시각, 외출 가능 0 |
| 시각 파싱 실패 | 도착: 화면에서 데모값(10:30) 사용, 출발: 연결편 없음으로 처리 |
