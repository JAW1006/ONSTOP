# Time-Fit — 코스 가용 시간과 자동 추천

> 상태: 초안 · 최종 수정 2026-10-16
> 코드: [`src/domain/time-fit.ts`](../../src/domain/time-fit.ts), [`travel.ts`](../../src/domain/travel.ts) · 테스트: [`time-fit.test.ts`](../../src/domain/time-fit.test.ts) · 용어: [GLOSSARY](../GLOSSARY.md)

## 정의

### 기존 동작 (레거시 `Course` 1747–1798줄, `SavedCourseScreen` 1990–2010줄 — 같은 식 중복)
```
BUDGET = returnBy − arrive                         (= Time-Safe 표시값)
used   = PREP + roomMove
       + Σ (moveᵢ + durᵢ)                          (moveᵢ = 숙소→장소ᵢ)
       + (장소 있으면 move_last, 없으면 roomMove)  (복귀 구간)
remain = BUDGET − used,  over = remain < 0
```

#### A6 — 기존 동작 vs 결정된 방식
| | 기존 동작(레거시, 별 모양) | 결정된 방식(순차 경로) |
|---|---|---|
| 구간 | 공항→숙소, 그리고 장소마다 **숙소→장소** | 공항→호텔, 호텔→장소1, 장소ᵢ→장소ᵢ₊₁, **장소N→호텔(B1)**, 호텔→공항 |
| 복귀 | 숙소→마지막 장소 시간을 **재사용** | 호텔→공항 **실제 구간**(장소가 있으면 그 전에 장소N→호텔) |
| 지도 vs 예산 | 지도는 순차 구간, 예산은 별 모양 → 숫자 불일치 | 지도 칩 합계 = 예산의 이동 분 |
| "환승 내 가능" | 후보를 끝에 붙인 별 모양 계산 | 후보를 끝에 붙인 순차 경로(…→마지막→후보→호텔→공항) |
| 자동 추천 정렬 | 카테고리마다 `숙소→장소 + 체류` 오름차순 | **같음**(정렬 기준 유지) |
| 자동 추천 판정 | 별 모양 used ≤ available | 순차 경로 used ≤ available, 블록이 있으면 + 호텔 복귀 ≤ 블록 종료 |
| 구간 시간 출처 | 숙소→장소 실측, 실패 시 데이터 `move` | **코스 빌더: 보수적 근사만**(도보: 직선 × `WALK_DETOUR_FACTOR` ÷ 4.5km/h, 그 외: 직선 × `CONSERVATIVE_MIN_PER_KM`) → "약 N분". **코스 확정(저장) 후에만** 구간별 실제 경로 조회(캐시), 실패 시 같은 근사 — 2026-10-16 결정(ODsay 쿼터 확인 전) |

기존 함수(`courseUsedMin`, `buildCourseTimeline`, `autoBuild`)는 **레거시 비교용**으로 남긴다. 새 화면은 아래 순차 경로 함수만 쓴다.

#### 순차 경로 공식 (`sequentialCourse`, `autoBuildSequential`, `fitsSequential`, `returnPlan`)
```
legs   = [공항→호텔, 호텔→장소1, …, 장소N−1→장소N, 장소N→호텔, 호텔→공항]   (N + 3개)
         장소 없으면 [공항→호텔, 호텔→공항]                                   (2개)
used   = Σ legs + Σ 체류                                         (준비 제외 = 코스 사용 시간)
일정 요약: 사용 = used + COURSE_PREP_MIN, 가용 = 외출 가능 시간, 여유 = 가용 − 사용

타임라인(공항 밖 시각 S부터):
  S + COURSE_PREP_MIN + legs[0]                  = 체크인
  이전 출발 + legs[i]                             = 장소ᵢ 도착,  + 체류ᵢ = 장소ᵢ 출발
  마지막 출발(장소N, 없으면 체크인) + 장소N→호텔   = 호텔 복귀(장소 없으면 체크인)
  호텔 복귀 + 호텔→공항                          = 복귀 도착 예상

복귀 도착 목표       = returnBy (Time-Safe)
숙소 출발 기한       = returnBy − 호텔→공항
블록 종료            = 체크인 슬롯 + 상품 시간 (데이유즈 블록을 고른 경우만, 없으면 없음)
마지막 장소 출발 기한 = min(숙소 출발 기한, 블록 종료) − 장소N→호텔   (장소 없으면 숙소 출발 기한)
늦음                 = 복귀 도착 예상 > returnBy  (= 여유 < 0)
블록 초과(B1 제약)    = 장소가 있고 호텔 복귀 > 블록 종료

체크인 슬롯 정렬(alignCheckIn, 2026-10-16 결정):
  대기 = max(0, 슬롯 − 체크인)  → 모든 시각 + 대기, 코스 사용 시간 + 대기
```
- 호텔에 머무는 시간(휴식·샤워·짐 찾기)은 넣지 않는다(기존 "숙소 체류는 넣지 않는다" 유지). 짐 찾는 시간 별도 반영은 [STATUS](../STATUS.md) 후보.

#### 현재 공식 (A5까지 — 레거시 별 모양 기준, 비교용)
```
코스 가용 시간 available = max(0, 외출 가능 시간 − COURSE_PREP_MIN)
코스 사용 시간 used      = roomMove + Σ (moveᵢ + durᵢ) + (장소 있으면 move_last, 없으면 roomMove)
remain = available − used,  over = remain < 0
"환승 내 가능" = (담겨 있으면 현재 일정, 아니면 일정 + 그 장소)의 used ≤ available

일정 요약(화면 표기): 사용 = used + COURSE_PREP_MIN, 가용 = 외출 가능 시간, 여유 = 가용 − 사용 (= remain)

타임라인: 공항 밖 시각 → +COURSE_PREP_MIN → +roomMove(체크인) → 장소마다 +move(도착) +dur(출발) → +복귀 구간
```
- 숙소 체류(휴식)는 넣지 않는다(의도: 숙소는 거점).
- `move`는 실측 우선, 실패 시 데이터 더미값.

**자동 추천(`autoBuild`, 탐욕법 — 기존 동작 그대로)**
1. 선택 카테고리(없으면 `ACT_KEYS`)를 온보딩 관심사 순서로 정렬(관심사에 없는 건 뒤로, 같은 순위는 원래 순서).
2. 카테고리마다 `move + dur` 오름차순으로 보며, 지금까지 고른 일정에 더해도 `used ≤ available`인 **첫 장소 1곳**을 담는다.

**이동시간 (기존 동작 그대로)**
| 직선거리 | 수단 | 분 |
|---|---|---|
| ≤ `WALK_MAX_KM` | 도보(추정) | `max(1, round(km ÷ WALK_SPEED_KMH × 60))` |
| ≥ `TRANSIT_MIN_KM` | ODsay 대중교통, 실패 시 자동차 | `max(1, round(durationMin))` |
| 그 사이 | 카카오모빌리티 자동차 | `max(1, round(durationSec ÷ 60))` |
| 실측 전 실시간 장소 | 임시값 | `max(1, round(km × LIVE_PLACE_MIN_PER_KM))` |

## 엣지 케이스
| 상황 | 처리 |
|---|---|
| 외출 불가(외출 가능 0) | 코스 가용 0 |
| 숙소 미선택 | 자동 추천 버튼 비활성, used 0 |
| 장소 간 이동 | 기존 동작: 각 장소의 숙소→장소 시간 · 결정된 방식: 실제 장소ᵢ→장소ᵢ₊₁ 구간(A6) |
| 복귀 구간 | 기존 동작: 마지막 장소의 숙소→장소 시간 재사용 · 결정된 방식: 장소N→호텔→공항(B1) |
| 블록 미선택 | 호텔 복귀 제약 없음(코스 가용 시간만) |
| 블록 초과 | 경고 + 마지막 장소 출발 기한을 블록 종료 기준으로 당김. 자동 추천·"환승 내 가능"은 제약을 넘는 장소를 빼고 판정 |
| 카테고리당 1곳 | 자동 추천은 시간이 남아도 카테고리당 1곳만 |
| 버튼 문구 "OR-Tools 최적화" | 실제는 탐욕법(A7, [STATUS](../STATUS.md)) |
