> 상태: **확정(2026-10-16 결정 반영) — 구현 중** · 최종 수정 2026-10-16

## 목적
환승객이 데이유즈 숙소 이용을 **호텔에 요청**하고, 호텔이 확인하면 확정되는 첫 예약 흐름이다. **결제는 하지 않는다**(ADR-0004 결정 전). 앱은 체크인 시각과 상품(시간 블록)을 고르게 돕고, 그 선택이 코스(호텔 복귀)와 연결편 복귀 시각에 맞는지 보여준다.

레거시 흐름은 "결제하기 → 예약 완료(가짜 QR)"였다. 새 화면은 **"예약 요청 → 호텔 확인"**이다. 확정 전에는 "예약 완료"라고 쓰지 않는다.

## 요청 모드 2가지
| 모드 | 조건 | 사용자가 고르는 것 | 호텔이 회신하는 것 |
|---|---|---|---|
| **(a) 상품 요청** | 호텔 가격표(`offer.products`)가 있다 | 체크인 슬롯 + 상품(블록·가격) | 가능 여부(확정/거절) |
| **(b) 견적 요청** | 가격표가 없다 | 체크인 슬롯만. 희망 이용 시간 = 슬롯 → **숙소 출발 기한**(복귀 목표 − 호텔→공항)으로 자동 | 가격 + 가능 여부 |

가격표 출처(A9):
- 운영: 호텔 데이터 `offer`만 쓴다.
- 데모: `offer`가 없으면 **데모용 가격표 파일**(`src/data/demo-offers.json`, 사용자가 채움)을 쓰고 "데모 가격" 배지를 붙인다. 두 곳 모두 비어 있으면 (b) 견적 요청이 된다.
- 레거시 계산식(`roomHourTiers`)은 쓰지 않는다.

## 호텔 참여 상태와 노출
| 상태 | 값 | 운영 | 데모 |
|---|---|---|---|
| 확정 | `confirmed` | 홈·코스·예약에 노출, 요청 가능(배포 조건 충족 시) | 노출 |
| 협의 중 | `negotiating` | **노출 안 함** | 노출 + "협의 중" 표시 |
| 미참여 | `none` | **노출 안 함** | 노출 + "미참여" 표시 |

- 데이터 기본값은 `none`이다(확인 전). 값은 인터뷰 결과로 채운다([data-verification](../data-verification.md) 수동 입력 구역).
- 운영에서 예약 요청을 켜는 기준과 대안(정보 보기 모드)은 [STATUS](../../STATUS.md) "예약 요청 운영 기준"에 있다.

## 데모 모드와 운영 배포 금지 (B6)
- **데모 표시가 있는 환경에서만 요청 버튼이 동작한다.** 데모 여부는 `VITE_DEMO_MODE=true` 또는 개발 서버(`npm run dev`)로 정한다.
- 데모에서는 모든 예약 화면 상단에 "데모 — 요청이 호텔에 전송되지 않아요" 띠를 표시한다.
- 데모 표시가 없는 환경(운영 빌드)에서는 버튼이 비활성이고 "예약 요청은 아직 준비 중이에요"를 표시한다. 요청을 만들 수 없다.
- 데모의 요청은 **메모리에만** 저장한다(새로 고침하면 사라짐). 호텔 응답(확정·거절)도 오지 않는다.
- 서버가 요청을 실제로 호텔에 전달하기 전까지 **운영(프로덕션) 배포 금지**: [STATUS](../../STATUS.md), [ADR-0005](../../decisions/ADR-0005-environments-deploy.md).

## 시간 계산 (공식: dayuse-pricing "예약 시각 계산")
```
코스 체크인(호텔 도착) = 코스 계산값(진입 ①) 또는 공항 밖 + 준비 + 공항→호텔 근사(진입 ②)
슬롯 지연 = max(0, 고른 슬롯 − 코스 체크인)          ← 슬롯이 늦으면 코스 전체를 그만큼 늦춘다(2026-10-16 결정)
숙소 복귀 = 코스 숙소 복귀 + 슬롯 지연                  (장소 없으면 숙소 복귀 계산 안 함)
공항 복귀 예상 = 코스 공항 복귀 + 슬롯 지연
이용 종료 = 슬롯 + 상품 시간(모드 a) / 숙소 출발 기한(모드 b)
블록 초과(B3) = 장소가 있고 숙소 복귀 > 이용 종료
복귀 늦음     = 공항 복귀 예상 > 복귀 목표
```
요청이 진행 중(요청됨·확정)이면, 같은 숙소의 코스 화면에도 이 슬롯과 이용 종료가 제약으로 들어간다. 코스 시작을 슬롯에 맞추고, 숙소 복귀 ≤ 이용 종료를 판정한다(time-fit B1).

### 거절·만료 시 대안 숙소 제안
- 후보: 노출되는 다른 숙소(거절된 숙소 제외)를 **공항→숙소 근사 이동시간이 짧은 순**으로 최대 3곳.
- 각 후보: 이름 · 공항에서 약 N분 · 모드(가격표 있음 = "가격 보기", 없음 = "견적 요청") → `/booking/:id`.
- 코스가 거절된 숙소 기준이면 "코스를 새 숙소로 다시 만들어 주세요" + 코스 만들기 버튼. 장소는 숙소가 바뀌면 다시 계산해야 한다.
- 거절·만료된 요청은 진행 중이 아니므로 새 요청을 바로 보낼 수 있다(B8).

| 호텔 데이터(참여 상태·가격표·연락처·취소 규정) | 인터뷰 |

## 빈/오류/로딩 상태
| 상황 | 처리 |
|---|---|
| 항공편 조회 중 | 체크인 후보·시간 계산 자리에 로딩, 버튼 비활성 |
| 항공편 조회 실패 | Time-Safe와 같은 오류 + 버튼 비활성 |
| 코스 경로 조회 실패 | 근사 + "약"(저장된 코스와 같음) |
| 모든 상품이 고른 슬롯에 시작 불가 | "이 시각에는 시작할 수 있는 상품이 없어요" + 다른 슬롯 선택 |
| 요청 저장 실패(서버 연결 후) | 입력값 유지 + "보내지 못했어요. 다시 시도해 주세요" |

## 레거시와 다르게 하는 점
| 항목 | 레거시 | 새 화면 | 근거 |
|---|---|---|---|
| 흐름 | 결제하기 → 예약 완료 | 예약/견적 요청 → 호텔 확인(요청됨/확정/거절/만료/취소됨) | 2026-10-16 결정, ADR-0004 제안 |
| 가격 | 기본가 + 계산식(`TIER_STEP_RATIO`) | 호텔 가격표 그대로, 없으면 견적 요청 | A9 |
| 체크인 기준 이동시간 | 정적 `move` | 코스의 실제 경로(없으면 근사) | A10 |
| 체크아웃 경고 | 체크아웃 > 공항 복귀 추천 시각 | **숙소 복귀 > 이용 종료**(B3) + 복귀 늦음, 확인 체크 필요 | B1 |
| 늦은 슬롯 | 코스와 무관 | 코스 전체를 슬롯만큼 늦춰 계산 | 2026-10-16 결정 |
| 완료 화면 | "예약 완료" + 가짜 QR + "알림 켜짐" | 상태 배지, QR 없음, 알림 문구 없음 | 기능 없는 표시 제거 |
| 결제 수단 문구 | "간편결제 · Alipay · WeChat Pay · Card" | 없음 | 결제 없음 |
| 연락처 | 없음 | 이름(영문 허용)·이메일만 | ADR-0003, B4 |
| 취소 | 없음 | 요청됨은 즉시 취소, 확정은 호텔 문의 | B8 |
| 사진 | 레거시 사진 | 틴트 배경 + 아이콘 | legal 0-1 |
| 숙소 노출 | 10곳 전부 | 운영은 참여 확정 호텔만 | 2026-10-16 결정 |

## 결정 기록 (2026-10-16 사용자)
| # | 결정 |
|---|---|
| B1 | 코스 = 공항 → 호텔 → 장소들 → 호텔 → 공항. 숙소 복귀 ≤ 이용 종료가 코스 제약 |
| B2 | 코스 없이도 요청 허용(근사, "약") |
| B3 | 블록 초과·복귀 늦음은 경고 + 확인 체크 |
| B4 | 이름(영문 표기 허용) + 이메일만 |
| B5 | 요청됨·확정·거절·만료·취소됨. 만료 시간은 호텔 응답 속도에 따라(인터뷰), 거절·만료 시 대안 숙소 제안 |
| B6 | 화면 먼저 + 메모리 저장(데모 표시). 데모 표시가 없는 환경에서는 버튼 비활성, 서버가 호텔에 전달하기 전까지 운영 배포 금지 |
| B7 | 외출≠입국 안내 안 A(고정 안내) + 버튼 위 한 줄 |
| B8 | 진행 중인 요청 1건. 요청됨은 즉시 취소, 확정 후는 호텔 문의(연락처·규정 표시). "확정 후 취소 요청" 상태는 STATUS 후보 |
| 슬롯 | 슬롯이 코스 호텔 도착보다 늦으면 코스 전체를 늦춰 계산 |
| 가격 | 가격표 있으면 상품 요청, 없으면 견적 요청. 데모는 데모용 가격표 파일(사용자 입력) |
| 노출 | 참여 상태(확정/협의 중/미참여), 운영은 확정만 |
