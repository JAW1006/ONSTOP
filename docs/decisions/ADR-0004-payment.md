# ADR-0004: 결제·정산 구조

> 상태: **제안(결정 전)** · 최종 수정 2026-10-16
> 첫 예약은 **결제 없이 "예약 요청 → 호텔 확인"**으로 운영한다(2026-10-16 결정, [screens/booking](../design/screens/booking.md)). 이 ADR은 그 다음 단계의 결제 구조를 정하기 위한 비교다.
> 법적 판단은 하지 않는다 — "확인 항목"은 [legal-checklist](../legal-checklist.md)에서 전문가 확인.

## 배경
- 수익 모델(사업 계획, 미검증): 데이유즈 12%, 액티비티 15%, CPC 200~500원.
- 사용자는 외국인 환승객 — 해외 카드·해외 간편결제, 일정 변동(항공편 지연)이 잦다.
- 호텔마다 이미 쓰는 예약·결제 방식이 다를 수 있다 → 호텔 인터뷰로 확인([product/hotel-interview](../product/hotel-interview.md)).

## 선택지
### A. 플랫폼 결제·정산 — 고객이 플랫폼에 결제, 플랫폼이 수수료를 떼고 호텔에 정산
| 장점 | 단점 |
|---|---|
| 결제 경험이 하나로 통일(외국인 결제 수단을 플랫폼이 책임지고 갖춤) | 고객 돈을 플랫폼이 받아 보관·정산 → 요건·책임 범위가 커질 수 있음(아래 확인 항목) |
| 예약 확정 = 결제 완료로 노쇼·취소 처리를 플랫폼 규칙으로 일관되게 | PG 하위몰·정산 기능, 환불·분쟁(차지백) 대응을 플랫폼이 직접 |
| 수수료가 자동 확보(미수 없음) | 호텔별 정산 주기·세금계산서·대사(reconciliation) 업무 |
| 결제 데이터로 업무 지표 정확 | 초기 개발·심사 기간이 길다 |

### B. 호텔 직접 결제 + 플랫폼 월 정산 — 고객은 호텔에 결제(현장 또는 호텔 결제 링크), 플랫폼은 월말에 수수료 청구
| 장점 | 단점 |
|---|---|
| 플랫폼이 고객 돈을 다루지 않음 — 구조 단순, 빨리 시작 | 결제 수단이 호텔마다 다름(해외 카드·간편결제 미지원 호텔 가능) |
| 호텔이 익숙한 방식(현장 결제 등) 유지 | 노쇼 시 손실이 호텔에, 플랫폼은 노쇼·취소를 강제할 수단이 약함 |
| "예약 요청 → 호텔 확인"(첫 단계)과 자연스럽게 이어짐 | 수수료 대상 매출 확인을 호텔 보고에 의존 → 누락·분쟁 가능, 증빙 필요 |
| 초기 비용 적음 | 고객 경험이 호텔마다 달라 일관성이 떨어짐 |

## 법적 확인 항목 (결론 없음 — [legal-checklist](../legal-checklist.md))

## 결정 전에 할 일
1. 호텔 5곳 인터뷰([product/hotel-interview](../product/hotel-interview.md)) — 예약금 수취 주체·정산·노쇼/취소·결제 수단.
2. PG 후보별 해외 카드·Alipay·WeChat Pay 지원, 수수료, 하위몰·정산 기능 확인(**미확인**).
3. 전문가에게 L1~L7 확인.

## 결과(예상)
- 인터뷰에서 호텔 대부분이 자체 결제를 원하고 해외 결제 수단이 갖춰져 있으면 B로 시작해 A로 옮기는 경로가 가능하다. 반대면 A. — 인터뷰 후 결정.
