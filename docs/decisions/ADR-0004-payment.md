# ADR-0004: 결제 연동 방식

> 상태: **초안(제안 — 결정 전)** · 2026-10-16 · 수수료·지원 수단은 아래에 적은 것 외에는 **미확인**(결제사 확인 필요)

## 배경
- 레거시 결제 화면 문구: "간편결제 · Alipay · WeChat Pay · Card" — 데모일 뿐 실제 결제는 없다.
- 수익 모델: 데이유즈 12%, 액티비티 15%, CPC 200~500원(사업 계획, 미검증) — 즉 **플랫폼이 고객 돈을 받아 숙소에 정산**하는 구조인지, **숙소가 직접 받고 수수료만 청구**하는 구조인지에 따라 결제 설계와 법적 지위가 크게 달라진다([legal-checklist](../legal-checklist.md) "통신판매중개·정산").
- 사용자는 외국인: 해외 발행 카드, 중국·동남아 간편결제 비중이 높을 것으로 예상(근거 미확인).

## 결정 (제안)
1. **먼저 정산 구조를 정한다**(아래 두 가지 중) — 결제 연동은 그 다음.
2. 결제는 **PG(결제대행) 연동**으로 하고 카드 정보는 앱·서버에 저장하지 않는다.
3. 1차 수단: 해외 카드(Visa·Master 등) + Alipay·WeChat Pay 지원 여부를 PG 후보별로 확인.

| 정산 구조 | 내용 | 영향 |
|---|---|---|
| A. 플랫폼 결제 후 정산 | 고객 → 플랫폼(PG) → 숙소 정산(수수료 공제) | PG 하위몰·정산 기능 필요, 통신판매중개·전자금융 관련 확인 |
| B. 숙소 직접 결제 | 고객 → 숙소, 플랫폼은 수수료 청구 | 결제 구현 단순, 숙소별 결제 수단 차이, 예약 확정 시점 관리 어려움 |

## 대안 (결제 연동 방식)
| 대안 | 확인할 것 |
|---|---|
| 국내 PG 직접 연동(예: 토스페이먼츠·KG이니시스·NHN KCP 등) | 해외 카드·Alipay·WeChat Pay 지원 여부, 외국인 결제 승인율, 수수료 — **미확인** |
| 결제 통합 서비스(예: 포트원) | 여러 PG 동시 연동, 수수료 구조 — **미확인** |
| 해외 결제 서비스(예: Stripe) | 한국 법인 가입 가능 여부, 국내 숙소 정산 — **미확인** |

## 결과(예상)
- 확인 필요: 환불 규칙(체크인 전/후, 항공편 지연 시), 부분 환불, 현금영수증·세금계산서, 정산 주기.
- 결제가 붙기 전까지는 예약 화면을 "결제 없이 예약 요청"으로 운영하는 방안도 검토(숙소 확인 후 확정).
