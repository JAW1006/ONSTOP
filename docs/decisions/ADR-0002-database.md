# ADR-0002: 데이터베이스 선택

> 상태: **초안(제안 — 결정 전)** · 최종 수정 2026-10-18
> 2026-10-18: 예약 요청 저장이 이 제안대로 **먼저 구현됐다**(아래 "구현된 부분"). 공급자는 **여전히 결정 전**이다 — 구현을 벤더 중립으로 두어 나중에 옮길 수 있게 했다.

## 배경
- 지금은 저장소가 없다. 예약·저장된 코스는 브라우저 메모리에만 있어 새로 고침하면 사라진다.
- 저장해야 할 것: 예약(숙소·체크인·시간대·금액·상태), 코스(숙소·장소 순서), 사용자(비회원 연락처 또는 회원), 결제 내역, 제휴 숙소·장소 데이터(운영자가 수정), 감사 로그.
- 배포는 Render를 쓰고 있다(무료 웹 서비스 1개).
- 제약: 카카오 로컬 API 응답은 **저장해 재사용하면 안 된다**는 카카오 측 답변이 있다([operations/external-apis](../operations/external-apis.md)) → 실시간 장소는 DB에 저장하지 않는다.

## 결정 (제안)
**관리형 PostgreSQL** 하나로 시작한다. 후보 중 운영 위치는 아래 표에서 고른다.

| 항목 | 제안 | 구현 상태 |
|---|---|---|
| 엔진 | PostgreSQL — 예약·결제처럼 관계·트랜잭션이 중요한 데이터 | 적용 (`pg`, 표준 SQL만) |
| 접근 | 서버(API)만 DB에 접근. 프런트는 API만 호출 | 적용 (`server/booking.js`) |
| 스키마 관리 | **SQL 마이그레이션 파일**(`server/migrations/*.sql`). ORM·마이그레이션 도구는 서버 TS 전환 때 다시 본다 | 적용 |
| 환경 | dev / staging / prod DB 분리([ADR-0005](ADR-0005-environments-deploy.md)) | **미적용** — 지금은 `DATABASE_URL` 한 개 |
| 개인정보 | 저장 항목 최소화, 보관 기간·파기 규칙([legal-checklist](../legal-checklist.md)) | 최소화 적용(이름·이메일만), **보관 기간·파기 미정** |

## 구현된 부분 (2026-10-18)
예약 요청 저장([api/booking-requests](../api/booking-requests.md))을 위해 먼저 들어갔다. 공급자를 고르지 않고도 진행할 수 있게 **벤더 중립**으로 만들었다.

| 결정 | 내용 | 왜 |
|---|---|---|
| 연결 | `DATABASE_URL` 하나(표준 Postgres 접속 문자열) | 공급자를 바꿀 때 환경변수만 교체 |
| 스키마 | `server/migrations/*.sql`을 이름순 적용, 적용분은 `schema_migrations`에 기록 | 스키마가 코드가 아니라 파일에 남아 어디서든 같은 결과 |
| SQL 범위 | **표준 PostgreSQL만.** 벤더 전용 기능·확장 금지 | 공급자를 옮겨도 같은 파일이 그대로 돈다 |
| 되돌리기 | down 스크립트 없음 — 바꿀 때 새 번호 파일을 더한다 | 운영 데이터가 없는 단계에서 복잡도만 늘린다 |
| SSL | 호스트가 localhost가 아니면 SSL, 체인 검증은 끔(`rejectUnauthorized: false`) | 관리형 Postgres가 자체 서명 체인을 쓰는 경우가 많다. **공급자 확정 후 CA 번들 지정으로 바꿀 것** |

지금은 **예약 요청만** DB에 있다. 저장된 코스·숙소 데이터는 아직 파일·메모리다.

## 대안
| 대안 | 장점 | 단점 / 확인 필요 |
|---|---|---|
| **Render PostgreSQL** | 지금 배포와 같은 곳, 네트워크 단순 | 요금·백업·무료 플랜 만료 조건 **미확인** |
| **Supabase(Postgres)** | 인증·스토리지까지 한 곳, 관리 화면 | 서울 리전·요금·데이터 위치 **미확인**, 벤더 기능에 묶일 수 있음 |
| **Firebase(Firestore)** | 실시간·푸시와 궁합 | 문서 DB — 예약·결제 정합성 관리가 어려움 |
| 정적 JSON 유지 | 비용 없음 | 예약 저장 불가 — 서비스 운영 불가 |

## 결과(예상)
- (+) 예약·코스가 남고, 운영자가 숙소 데이터를 고칠 수 있다.
- (−) 개인정보 처리 책임이 생긴다 → 1단계에서 [legal-checklist](../legal-checklist.md) 확인 필요.
- 결정 전 확인: 예상 예약 수(일/월), 데이터 보관 위치(국내 여부), 백업·복구 요구 수준.

## 결정 전에 할 일 (공급자 확정)
| # | 확인 항목 | 왜 막혀 있나 |
|---|---|---|
| 1 | Render PostgreSQL vs Supabase — 요금·무료 플랜 만료·백업·복구 | 위 "대안" 표의 **미확인** 항목 |
| 2 | 데이터 저장 **리전**(국내 여부) | [legal 2-4](../legal-checklist.md) 국외 이전 고지·동의와 직접 연결 |
| 3 | 보관 기간·파기 규칙 | [legal 2-1](../legal-checklist.md). 정해지기 전까지 자동 삭제 작업을 만들지 않는다 |
| 4 | dev / staging / prod DB 분리 시점 | [ADR-0005](ADR-0005-environments-deploy.md) staging 구성과 함께 |
| 5 | SSL 체인 검증을 켤 방법(CA 번들) | 공급자가 정해져야 번들을 지정할 수 있다 |

위가 정해지면 이 ADR을 **확정**으로 바꾸고, 바뀐 항목만 새 마이그레이션 파일로 반영한다.
