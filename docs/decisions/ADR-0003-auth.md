# ADR-0003: 인증 방식 — 회원 / 비회원

> 상태: **초안(제안 — 결정 전)** · 2026-10-16

## 배경
- 사용자는 **환승 중인 외국인**이다. 한 번 쓰고 끝나는 경우가 많고, 가입 절차가 길면 이탈한다.
- 국내 휴대폰 본인인증·국내 간편 로그인을 못 쓰는 사용자가 많다.
- 그래도 예약 확인·변경·환불, 결제 분쟁 대응을 위해 **예약을 다시 찾을 수단**은 필요하다.
- 레거시 마이 화면에는 "여권 인증(준비중)" 메뉴가 있다 — 여권 정보 수집 여부는 개인정보 측면에서 별도 검토 대상.

## 결정 (제안)
**비회원 예약을 기본**으로 하고, 회원(소셜 로그인)은 나중에 선택 사항으로 붙인다.

| 항목 | 제안 |
|---|---|
| 예약 | 비회원: 이메일(필수) + 이름. 예약 완료 시 예약번호 + 조회용 비밀 링크(또는 이메일 OTP) |
| 예약 조회 | 예약번호 + 이메일 OTP, 또는 이메일로 받은 링크 |
| 회원(후순위) | 소셜 로그인 — Google·Apple 우선(외국인 보급률), 지역별로 LINE·WeChat·Kakao 검토 |
| 여권 정보 | **수집하지 않는 것을 기본**으로. 숙소 체크인에 필요하면 숙소가 현장에서 확인(제휴 조건 확인 필요) |
| 세션 | 서버 발급 토큰(httpOnly 쿠키), 비회원 조회 권한은 예약 1건 범위로 제한 |

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 회원 필수(이메일 가입) | 재방문·마케팅 | 환승객 이탈, 비밀번호 관리 부담 |
| 국내 휴대폰 본인인증 | 국내 표준 | 외국인 대부분 불가 |
| 소셜 로그인만 | 가입 빠름 | 국가별 지원 서비스가 달라 누락 사용자 발생, 앱 심사·약관 부담 |
| 인증 없음(현재) | 단순 | 예약 조회·환불 불가 |

## 결과(예상)
- (+) 첫 예약까지 단계가 짧다.
- (−) 이메일 오입력 시 예약 조회 불가 → 예약 완료 화면에서 확인 단계 필요.
- 확인 필요: 결제사(PG)가 요구하는 구매자 정보 항목, 개인정보 수집 동의 문구([legal-checklist](../legal-checklist.md)).
