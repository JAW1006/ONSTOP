# ADR-0006: 복귀 알림

> 상태: **초안(제안 — 결정 전)** · 최종 수정 2026-10-16
> 방향(2026-10-16 사용자): **앱 안 카운트다운·캘린더 추가 먼저 → 앱 출시 때 기기 내 예약 알림으로 이동 → 웹 푸시는 보조.**

## 배경
- 서비스의 가장 큰 위험은 **사용자가 연결편을 놓치는 것**이다. 공항 복귀 시각을 놓치지 않게 알려야 한다.
- 레거시에는 "복귀 30분 전 푸시 알림 예약됨" 문구만 있고 기능이 없었다 → 2026-10-16 문구 삭제.
- 지금 앱은 웹(모바일 브라우저)이다. 나중에 Capacitor로 앱을 낼 수 있다([roadmap](../product/roadmap.md) "앱 전환 대비").

## iOS 웹 푸시 제약 — Apple(WebKit) 원문 확인
출처: WebKit 블로그 "Web Push for Web Apps on iOS and iPadOS", Brady Eidson·Jen Simmons, **2023-02-16** — [webkit.org/blog/13878](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) (Apple WebKit 팀 공식 블로그, 2026-10-16 원문 확인)

| 원문 | 의미 |
|---|---|
| "Now with iOS and iPadOS 16.4, we are adding support for Web Push to Home Screen web apps." | iOS·iPadOS **16.4 이상**, 대상은 **홈 화면 웹 앱** |
| "A web app that has been added to the Home Screen can request permission to receive push notifications" | 홈 화면에 추가된 웹 앱만 권한 요청 가능 |
| 권한 요청은 "in response to direct user interaction"(예: 구독 버튼 탭) | 페이지를 열자마자 요청 불가, 버튼 등 사용자 동작 필요 |
| 매니페스트의 display를 "standalone or fullscreen"으로 하면 "that site becomes a Home Screen web app" | 웹 앱 매니페스트 필요 |

원문에서 확인 안 된 것(2차 자료만 — **미확인**): Safari 탭에서 권한 요청 불가 여부의 명시, 설치 안내 배너·설치 API 부재, 일부 환경의 신뢰성 문제, EU 지역 홈 화면 웹 앱 제한.

→ 환승 중인 외국인이 "홈 화면에 추가"까지 할 가능성은 낮다고 본다(추정, 근거 없음). iOS에서 웹 푸시만으로 알림을 보장할 수 없다.

## 결정 (제안)
| 단계 | 방식 | 내용 | 시점 |
|---|---|---|---|
| 1 | **앱 안 카운트다운** | 홈·코스·예약 화면 상단에 "공항 복귀까지 N분 / 마지막 장소 출발까지 N분" 상시 표시, 기한이 가까우면 강조. 항공편 지연으로 복귀 시각이 바뀌면 다시 계산(지금 2분 재조회 + 변경 배너 있음) | 웹, 우선 |
| 1 | **캘린더 추가(.ics)** | 복귀 시각·마지막 출발 기한을 기기 캘린더 일정 + 알림으로 저장 — iOS·Android 모두 OS 알림을 쓸 수 있다 | 웹, 우선 |
| 2 | **기기 내 예약 알림(로컬 알림)** | 앱 출시 때 캘린더 대신(또는 함께) 앱이 기기에 예약 알림을 건다 — 서버 푸시가 필요 없다. 기기별 예약 알림 개수 제한 등 세부는 **미확인**(앱 결정 시 확인) | 앱 출시 |
| 3 | 웹 푸시(보조) | Android·데스크톱 우선. iOS는 홈 화면 웹 앱 사용자만 — 설치 안내 화면 필요 | 필요 시 |
| (검토) | 메시지 알림 | 이메일·SMS·메신저 — 비용·개인정보 수집 범위 확인 | 미정 |

구현 구조: 알림을 `features/alerts`에 모으고 "알림 예약(시각, 문구)" 인터페이스 하나로 — 웹은 캘린더 파일, 앱은 기기 알림으로 바꿔 끼운다.

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 웹 푸시 먼저 | 앱을 닫아도 알림 | iOS 제약(홈 화면 웹 앱만, 16.4+) — 상당수 사용자에게 안 감 |
| 네이티브 앱 먼저 | 알림 확실 | 개발·심사·설치 부담, 일회성 사용자에 맞지 않음 |
| 알림 없음 | 단순 | 핵심 위험(연결편 놓침) 방치 |

## 결과(예상)
- (+) 설치 없이 모든 사용자에게 최소한의 안내(화면 + 캘린더).
- (−) 웹에서는 앱을 닫으면 카운트다운이 안 보인다 → 캘린더 알림이 보완.
- 면책 문구: 알림은 보조 수단이며 탑승 책임은 이용자([legal-checklist](../legal-checklist.md) 6-4).
