# ADR-0006: 복귀 알림 — 웹 푸시 vs 앱 내 카운트다운

> 상태: **초안(제안 — 결정 전)** · 2026-10-16

## 배경
- 서비스의 가장 큰 위험은 **사용자가 연결편을 놓치는 것**이다. 공항 복귀 시각을 놓치지 않게 알려야 한다.
- 레거시에는 "복귀 30분 전 푸시 알림 예약됨" 문구만 있고 기능이 없었다 → 2026-10-16 문구 삭제.
- 앱은 웹(모바일 브라우저)이다. 네이티브 앱은 없다.

## iOS 웹 푸시 제약 (조사, 2026-10-16)
| 내용 | 출처 | 확인 상태 |
|---|---|---|
| iOS·iPadOS **16.4 이상**에서만 웹 푸시 지원 | [OneSignal — Web Push for iOS](https://documentation.onesignal.com/docs/web-push-for-ios), [Pushpad](https://pushpad.xyz/blog/does-safari-on-ios-support-web-push-notifications/) | 2차 자료로 확인, Apple 원문 **미확인** |
| **홈 화면에 추가해서 실행한 웹 앱**에서만 동작(Safari 탭에서는 안 됨) | 위 출처, [MoEngage](https://developers.moengage.com/hc/en-us/articles/13906923326100) | 2차 자료로 확인 |
| 웹 앱 매니페스트(display 설정)·HTTPS 필요, 권한 요청은 사용자 동작(버튼 클릭)으로만 | 위 출처 | 2차 자료로 확인 |
| "홈 화면에 추가" 설치 안내 배너·설치 API 없음 — 사용자가 직접 찾아야 함 | [MagicBell — PWA iOS limitations](https://www.magicbell.com/blog/pwa-ios-limitations-safari-support-complete-guide) | 2차 자료 |
| 일부 환경에서 처음엔 오다가 멈추는 신뢰성 문제 보고 | OneSignal 문서 | 사례 보고 수준 |
| EU에서 홈 화면 웹 앱 제한(iOS 17.4) 주장 | MagicBell 블로그 | **미확인** |

→ 환승 중인 외국인이 "홈 화면에 추가"까지 할 가능성은 낮다(근거 없음, 추정). iOS 사용자에게 웹 푸시만으로 알림을 보장할 수 없다.

## 결정 (제안)
| 순서 | 방식 | 내용 |
|---|---|---|
| 1 | **앱 내 카운트다운(기본)** | 홈·코스 화면 상단에 "복귀까지 N분 / 마지막 장소 출발까지 N분" 상시 표시, 기한이 가까우면 배너 강조. 화면을 열면 항상 보인다 |
| 2 | 캘린더 추가(.ics) | 복귀 시각·마지막 출발 기한을 기기 캘린더 알림으로 — iOS·Android 모두 OS 알림을 쓸 수 있다 |
| 3 | 웹 푸시(보조) | Android·데스크톱 Chrome 우선. iOS는 홈 화면 설치 사용자만 — 설치 안내 화면 필요 |
| 4 | (검토) 메시지 알림 | 이메일·SMS·메신저(국가별) — 비용·개인정보 수집 범위 확인 필요 |

공통: 항공편 지연으로 복귀 시각이 바뀌면 다시 계산해 갱신(지금 2분 폴링 + 변경 배너가 있음).

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 웹 푸시만 | 앱을 닫아도 알림 | iOS 제약이 커서 상당수 사용자에게 안 감 |
| 네이티브 앱 | 알림 확실 | 개발·심사·설치 부담, 일회성 사용자에 맞지 않음 |
| 알림 없음 | 단순 | 핵심 위험(연결편 놓침)을 방치 |

## 결과(예상)
- (+) 설치 없이 모든 사용자에게 최소한의 안내가 간다(화면 + 캘린더).
- (−) 앱을 닫으면 카운트다운은 안 보인다 → 캘린더 알림이 보완.
- 면책 문구 필요: 알림은 보조 수단이며 탑승 책임은 사용자에게 있다([legal-checklist](../legal-checklist.md)).
