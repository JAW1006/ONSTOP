# 모니터링과 에러 추적

> 상태: 초안 · 2026-10-16 · 도구는 제안(결정 전). 지금은 아무 모니터링도 없다.

## 무엇을 봐야 하나
| 영역 | 신호 | 왜 |
|---|---|---|
| 프런트 에러 | JS 예외, 렌더 오류, 지도 SDK 로드 실패 | 외국인 사용자는 문의 경로가 없어 조용히 이탈 |
| API 에러 | `/api/*` 5xx 비율, 업스트림 실패(공공데이터·카카오·ODsay) | 항공편 조회 실패 = 서비스 핵심 실패 |
| 외부 API 쿼터 | API별 일일 호출 수 / 한도 | ODsay·카카오모빌리티 한도 초과 시 기능 저하([external-apis](external-apis.md)) |
| 응답 시간 | 항공편 조회·구간 조회 p95 | 온보딩 대기 |
| 가용성 | 프런트·API 헬스체크 | Render 무료 플랜 유휴 정지 여부 **미확인** |
| 업무 지표 | 온보딩 완료, 외출 불가 비율, 코스 저장, 예약 시도·완료 | 서비스 판단 |

## 제안 구성
| 항목 | 제안 | 비고 |
|---|---|---|
| 에러 추적 | Sentry 같은 에러 추적 서비스(프런트·서버 공통) | 요금·데이터 위치 **미확인**. 개인정보(이메일·편명)를 이벤트에 넣지 않도록 필터 |
| 서버 로그 | Render 로그 + 구조화 로그(JSON: 시간·경로·상태·지연·업스트림) | 키·개인정보 로그 금지 |
| 쿼터 집계 | 서버에서 API별 일일 호출 수를 세어 하루 1회 기록, **한도의 80%에 경고** | DB 도입([ADR-0002](../decisions/ADR-0002-database.md)) 후 저장 |
| 헬스체크 | API `/health`(업스트림 호출 없이) + 외부 업타임 모니터 | 5분 간격 |
| 알림 | 5xx 급증, 쿼터 80%, 헬스체크 실패 → 운영자 메신저/이메일 | 채널 미정 |
| 업무 지표 | 개인정보 없는 이벤트 수집(동의 필요 여부 확인 — [legal-checklist](../legal-checklist.md)) | 도구 미정 |

## 장애 시 동작 (지금 앱이 하는 일)
| 실패 | 앱 동작 | 사용자에게 보이는 것 |
|---|---|---|
| 항공편 조회 | 오류 문구, 재조회 안내 | "일치하는 항공편이 없어요" 등 |
| 출국장 대기 | 기준값(50분) 사용 | "출국장 실시간 아님 · 예상치 사용" |
| 길찾기·대중교통 | 근사값 | "약 N분" |
| 주변 장소 | 정적 장소만 | 후보가 적어짐 |
| 카카오맵 SDK | 지도 대신 안내 | "지도를 불러올 수 없어요…" |

→ 대부분 **조용히 대체**된다. 그래서 사용자 화면이 아니라 모니터링으로 실패를 알아야 한다.
